# Implementation and provenance

The filter and PPD are newly authored source licensed under GPL-3.0-only. The implementation was informed by Brother's public [QL-1100/QL-1110NWB/QL-1115NWB Raster Command Reference 1.00](https://download.brother.com/welcome/docp100366/cv_ql1100_eng_raster_100.pdf), especially printed pages 5–6, 13–20 and 22–36. The manual is a reference, not a redistributed software component. Brother's proprietary binaries, XML, private UI and complete PPD are not distributed; the authored catalog records factual media names and numeric dimensions. System libcups is linked dynamically under its own system license.

The GPL `rastertoptch.c` from [printer-driver-ptouch](https://github.com/philpem/printer-driver-ptouch) was inspected during research for feasibility and architectural comparison. No source from that implementation is incorporated. Adapting its many printer models, alignment and compression paths would create a larger validation surface than this QL-1100-specific filter requires. A focused authored implementation with uncompressed raster rows was chosen over adapting that broad GPL filter or adding PackBits: the modest USB bandwidth cost buys a directly auditable wire format.

## Input contract

`rastertoql1100 job-id user title copies options [raster-file]` reads a CUPS raster stream from stdin or the named file. `--help` and `--version` are standalone informational modes. It never launches a process, opens the network, installs anything or talks directly to USB. The existing CUPS USB backend transports stdout. All diagnostics go to stderr; titles and user names are not interpolated into diagnostics.

Only uncompressed CUPS raster v1 (`RaSt`/`tSaR`) and v3 (`RaS3`/`3SaR`) streams are accepted. Compressed CUPS v2, PWG and Apple URF streams are rejected before libcups parses a page. Apple's tested `cgpdftoraster` produces uncompressed v3.

CUPS raster headers must specify 300 x 300 dpi, one channel, chunked color order, 1- or 8-bit pixels, and W, SW or K color space. For W/SW, values below 128 are black; for K, values at least 128 are black (1-bit values are expanded to 0/255). The PPD selects 1-bit K monochrome, allowing the upstream rasterizer to dither. Arbitrary 8-bit input receives a fixed threshold. Row stride must equal the packed width, with no additional row padding. Duplex/tumble and header copies above one are rejected. Copies belong to the filter argument, preventing double expansion.

The catalog and generated PPD cover 67 named driver choices plus two legacy aliases. See [MEDIA.md](MEDIA.md) for dimensions, provenance, deliberate normalization and limitations. The filter accepts the exact full-sheet raster or exact printable rectangle. Full-page input is cropped without rescaling. Banner pages are split into two to four left-to-right physical strips. Each physical strip receives its own raster page and counts toward the impression limit; copies keep each logical page's strip sequence together.

`PageSize`, `PageRegion` and `media`, if present, must select compatible named sizes or supported CUPS custom dimensions and agree with the header. Aliases with the same geometry and media identity may be mixed. Without selection, a header's physical dimensions select a named format or supported custom continuous format. Page dimensions expressed as fractional points allow a one-dot tolerance; integer legacy PageSize uses half a point. Raster widths and heights remain exact, except that a custom length may supply one fewer raster row, which is padded white to honor the protocol's 301–35434-dot physical-length range.

`AutoCut=True/False` defaults true. `CutMedia=0/4` selects no cut/automatic cutting. `CutEvery=1..255` defaults 1 and sets the physical-label cutting interval. `CutAtEnd=True/False` defaults true; end cutting is enabled only when automatic cutting is enabled. `PrintQuality=Speed/Quality` defaults Speed and controls the protocol's quality-priority flag. `Collate=True/False` defaults true. Resolution, ColorModel, sides and MirrorPrint options are checked when present; unsupported values are rejected. Other CUPS accounting and upstream layout options are ignored: they must already have been applied by the rasterizer.

## Bounded job validation

Input is first read into a private anonymous temporary file, capped at 64 MiB. A fixed-buffer preflight checks the magic, decodes and validates each raw header (including byte order), and computes every uncompressed page boundary against the exact spool length before libcups sees a page. This prevents libcups from allocating a row buffer from an unvalidated header and rejects every partial trailing header or pixel block. Complete headers and pixels are then read through system libcups, with page data converted into a second private temporary file capped at 64 MiB. Maximums are 100 logical input pages, 100 copies and 1000 physical impressions, including banner strips. Memory buffers remain fixed and all dimensions/strides are checked before pixel reads. No printer bytes are written until the entire input and converted job pass validation. Malformed late pages therefore do not trigger an earlier page to print. Storage errors and cancellation abort with an ERROR diagnostic. Temporary files are closed and removed when the process exits.

SIGTERM/SIGINT set a cancellation flag. Input and stdout use nonblocking descriptors with finite 250 ms readiness polling; named FIFO input opens nonblocking. This avoids the signal-before-blocking-call cancellation race, and descriptor flags are restored before exit. Broken stdout is an error, not a successful job. Output already accepted by the backend cannot be recalled; cancellation after output begins may leave a partial job or labels already printed.

## Printer stream

A job starts with 350 zero invalidate bytes, ESC @ initialization, raster mode and automatic-status notification disabled. Each page sets media type/width/length validation, recovery on, raster count, starting-page flag, automatic cutting, the selected 1–255 cut interval and optional cut-at-end. Die-cut media uses validity 0x8e, type 0x0b and zero feed; continuous media uses validity 0x86, type 0x0a, media length zero and 35-dot feed. Quality priority adds flag 0x40 to the print-information command. Printer output compression is explicitly disabled. Compressed CUPS input is also deliberately rejected: libcups can prefetch beyond a page and report a partial trailing header as ordinary EOF, so callback byte counts cannot prove complete compressed-job framing. Supporting that format would require another validated framing parser; the packaged macOS raster path does not need it.

Every raster is 162 bytes (1296 head pins). The first transmitted bits correspond to the right margin; image x coordinates reverse into that pin order. For 103 stock, the leftmost input dot maps to bit 1237 and rightmost to bit 38; for 102 stock those are 1219 and 56. MSB precedes LSB in each byte. The last impression uses control-Z feeding; earlier impressions use FF. Copies replay already validated spool pages, in collated or uncollated order.

There is no printer-status request/backchannel parser. The filter can validate intended media but cannot verify the loaded roll, lid state, cutter state or physical print completion. The printer checks the transmitted media fields; CUPS backend transport failures remain CUPS's responsibility. `INFO: Sent ... to CUPS backend` means byte transfer completed, not that a label physically printed. Physical offset, orientation, cut timing and error display need an actual printer validation.

The printing path uses the ARM64 executable and Apple's system libcups and USB backend. PPD/filter support is a legacy CUPS interface. Successful tests on the current machine do not establish support for future macOS versions; macOS 28 remains untested. Owner-reported physical testing is limited to the original 103 x 164 mm path; see VALIDATION.md.
